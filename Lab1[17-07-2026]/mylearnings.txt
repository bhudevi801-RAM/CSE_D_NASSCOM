# What you did today

### 1. Installed Git ✅

You installed Git on your computer.

**Why?**

* Git is a **version control system**.
* It keeps track of changes to your code.
* It lets you collaborate with others and upload code to GitHub.

### 2. Created a Fork ✅

You created a **fork** of the repository.

**Meaning:**

```
Original Repository
        │

Your Fork
```

A **fork** is your own copy of someone else's GitHub repository.

**Why is it useful?**

* You can edit it freely.
* The original repository is not affected.
* Common in open-source projects and assessments.

---

You cloned your fork to your computer.

# Important Terms

| Term              | Meaning                                              |
| ----------------- | ---------------------------------------------------- |
| Git               | Version control software                             |
| GitHub            | Website that stores Git repositories online          |
| Repository (Repo) | A project folder managed by Git                      |
| Fork              | Your own copy of someone else's repository on GitHub |
| Clone             | Download a GitHub repository to your computer        |
| VS Code           | Code editor where you write and edit code            |
| Local Repository  | The copy of the repository on your computer          |
| Remote Repository | The repository stored on GitHub                      |
| Branch            | A separate line of development (usually `main`)      |
| Commit            | A saved snapshot of your changes                     |
| Push              | Upload your commits to GitHub                        |
| Pull              | Download the latest changes from GitHub              |
| Origin            | The default name for the remote GitHub repository    |
| Main              | The default branch of the repository                 |
| Staging Area      | Where Git keeps files before committing              |

# What "Working Tree Clean" Means

When Git says:

```
working tree clean
```

it means:

* ✅ No files have been modified.
* ✅ Nothing needs to be committed.
* ✅ Your local repository matches the last commit.

---

# A Simple Way to Remember

Think of Git like saving a document:

* **Edit a file** → Write your work.
* **`git add`** → Select the pages you want to save.
* **`git commit`** → Click **Save** and give it a description.
* **`git push`** → Upload the saved version to GitHub.

# What happens at each step?

### 1️⃣ Fork

* Creates **your own copy** of someone else's repository on GitHub.

```
Original Repo
      │
      ▼
Your Fork
```

---

### 2️⃣ Clone

Downloads your GitHub repository to your computer.

```
GitHub
    │
    ▼
Your Computer
```

Command:

```bash
git clone <repository-url>
```

---

### 3️⃣ Open in VS Code

Open the cloned folder.

```
Local Repository
       │
       ▼
    VS Code
```

---

### 4️⃣ Edit files

Example:

```
README.md
notes.txt
main.py
```

or create new files.

---

### 5️⃣ Save

Press

```
Ctrl + S
```

Only your computer is updated.

❌ GitHub is **NOT** updated.

---

### 6️⃣ Check changes

```bash
git status
```

Git tells you:

* New files
* Modified files
* Deleted files

---

### 7️⃣ Stage files

```bash
git add .
```

Meaning:

> "Git, prepare these files for the next commit."

---

### 8️⃣ Commit

```bash
git commit -m "Added notes"
```

Meaning:

> Save a snapshot with a message.

Think of it as a checkpoint.

---

### 9️⃣ Push

```bash
git push origin main
```

Uploads your commits to GitHub.

Now everyone (or just you, if it's your fork) can see the updated code online.

# Easy way to remember

* 🍴 **Fork** = Make **your own copy** on GitHub.
* 📥 **Clone** = Download it to your computer.
* ✏️ **Edit** = Make changes in VS Code.
* 💾 **Save** = Save on your computer.
* 📋 **Status** = See what changed.
* 📦 **Add** = Tell Git which changes to include.
* 📸 **Commit** = Save a version (snapshot).
* ☁️ **Push** = Upload that version to GitHub.

This is the basic workflow you'll use for almost every GitHub project and coding assessment.
